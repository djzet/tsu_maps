# 2-й модуль: Алгоритмы приближенных вычислений

**Проект для студентов Томского государственного университета (ТГУ)**  
**Формат:** групповая работа (1–4 человека)  
**Цель:** реализовать набор алгоритмов приближённых вычислений + их визуализацию + полноценный
интерфейс в виде мобильного приложения.

**Важно:**

- Запрещено использовать готовые библиотеки/решения алгоритмов и генеративные ИИ для генерации кода.
- Обучающие данные/датасеты можно брать готовые.
- Всё, что касается реализации алгоритмов и их работы — только руками команды.
- Если делаете бонусный вариант — базовый можно пропустить (если не указано обратное).

---

## Что нужно сделать: пошаговый план

### Этап 1: Подготовка ресурсов — разметка карты

**Обязательно для всех алгоритмов!**

1. Выбрать карту:
   - Скриншот/экспорт из 2GIS, Google Maps или Яндекс.Карт (роща ТГУ + прилегающие территории).
2. Разметить карту на квадраты (grid):
   - Рекомендуемый размер ячейки: 5–10 метров (подбирайте так, чтобы дорожки были проходимы).
   - Формат хранения: 2D-массив (List<List<int>> или Grid в Flutter).
      - `0` — проходимо (дорожки, газоны без препятствий)
      - `1` — препятствие (здания, внутренние помещения, газоны, заборы)
3. Создать файл `data/map_grid.json` или `.dart` с готовой разметкой.
4. Добавить возможность редактирования сетки в приложении (для бонусов).
5. Проверить:
   - Все реальные дорожки должны быть проходимы (протестировать A* вручную).
   - Сохранить координаты ключевых точек:
      - кафе/столовые (для генетического и кластеризации)
      - достопримечательности рощи
      - коворкинги/библиотеки/аудитории
      - главные входы зданий
6. Добавить GPS-координаты (lat/lng) для каждой ячейки — понадобится для реального положения
   пользователя.

**Результат этапа:** готовый файл карты + визуализация сетки в приложении (можно на отдельном
экране "Debug Map").

### Этап 2: Структура мобильного приложения

Приложение должно иметь **3 главных раздела** (как указано в задании):

1. **Навигация по кампусу** (A*)
2. **Общепит** (Кластеризация + Генетический + Дерево решений + Нейронная сеть)
3. **Коворкинг и экскурсия** (Муравьиный алгоритм)

**Экраны (минимальный набор):**

- Splash / Onboarding
- Главный экран (BottomNavigationBar или Drawer) с 3 вкладками
- Карта (общая для всех алгоритмов)
- Экран выбора алгоритма / функции
- Экран визуализации каждого алгоритма (анимация!)
- Экран настроек + профиль студента

**Дополнительно для доп. баллов:**

- Определение текущего положения (Geolocator)
- Темная/светлая тема в стиле ТГУ
- Сохранение истории маршрутов

### Этап 3: Реализация алгоритмов

#### 3.1 A* (строим кратчайшие маршруты до кафе)

**Базовый вариант:**

1. На карте выбрать стартовую и конечную точку (тапом или поиском).
2. Запустить A* с одной эвристикой (Manhattan или Euclidean).
3. Показать маршрут (полилиния) или сообщение «маршрута нет».
4. Вывести длину пути и время (скорость 5 км/ч).

**Бонусный вариант:**

1. Возможность расставлять временные препятствия (ограждающие ленты — тап + drag).
2. Анимация поиска в реальном времени:
   - открытые клетки (рассматриваемые)
   - закрытые клетки
   - путь, который строится на каждой итерации
3. **Доп. баллы:** определение текущего положения пользователя (Geolocator) как стартовой точки.

**Визуализация:** цвета (зелёный — путь, красный — препятствия, жёлтый — открытые, синий —
закрытые).

#### 3.2 Алгоритм кластеризации (определяем зоны еды)

**Базовый вариант:**

1. На карте расставить точки кафе (или загрузить готовые координаты).
2. Реализовать **K-means** (или DBSCAN — на выбор).
3. Показать кластеры цветом + границы областей.
4. Возможность менять количество кластеров (k).

**Бонусный вариант:**

1. Реализовать 2–3 метрики расстояния:
   - Евклидово
   - Пешеходное (через A* — самое точное!)
2. Показывать, какие точки «спорные» (меняют кластер в зависимости от метрики) + легенду.

#### 3.3 Генетический алгоритм (маршрут покупки еды — TSP с условиями)

**Базовый вариант:**

1. Создать список блюд и заведений (минимум 8–10 заведений с меню).
2. Пользователь выбирает нужные блюда (чекбоксы).
3. Генетический алгоритм:
   - Популяция 50–100 особей
   - Кроссовер, мутация, элитизм
   - Фитнес: время + штрафы за отсутствие блюда/посуды/время работы
4. Показывать **лучшую особь** на каждой итерации (анимация).
5. Учитывать:
   - расстояния (A*)
   - время работы заведений
   - скорость 5 км/ч
   - ограничения меню

**Результат:** готовый маршрут + общее время.

#### 3.4 Муравьиный алгоритм (TSP + оптимизация коворкинга)

**Базовый вариант:**

1. Пользователь выбирает достопримечательности (чекбокс-лист).
2. Муравьиный алгоритм (ACO) строит путь обхода всех выбранных точек.
3. Показывать маршрут и длину.

**Бонусный вариант (Оптимизация коворкинга):**

1. Ввод количества студентов.
2. Начальная точка — группа студентов.
3. Локации: библиотека, читалки, коворкинги (с вместимостью и комфортом).
4. Муравьи исследуют пространство, оставляют феромоны.
5. Учитывать: длина пути + комфорт + уже выбранные муравьи.
6. Анимация муравьёв (рекомендуется видео: https://youtu.be/emRXBr5JvoY).

#### 3.5 Дерево решений (выбираем, куда пойти на обед)

**Базовый вариант:**

1. Создать экран загрузки CSV-текста (или встроить пример из задания).
2. Реализовать дерево решений (ID3/C4.5 — вручную).
3. Визуализировать дерево (можно в виде списка узлов или простого графа).
4. Ввод новых данных → проход по дереву → рекомендация + путь по узлам.

**Бонус:** оптимизация размера дерева (pruning) для красивой визуализации на телефоне.

**Данные:** использовать CSV из задания + можно расширить признаки.

#### 3.6 Нейронная сеть (оценка заведения)

**Базовый вариант:**

1. Экран рисования 5×5 пикселей (палец — чёрный/белый).
2. Простая нейронная сеть (MLP или даже Perceptron) на 25 входов.
3. Обучить на 10–20 примерах цифр 0–9.
4. Показывать распознанную цифру (оценка 0–9).

**Бонусный вариант:**

1. Сетка 50×50.
2. Более мощная сеть (можно CNN, но вручную — без библиотек).
3. Сохранение нарисованных оценок в историю.

### Этап 4: Интеграция и финальная сборка (5–7 дней)

1. Связать все алгоритмы с общей картой.
2. Добавить анимации (Flutter: AnimationController + Hero).
3. Реализовать экран «Помощь с навигацией», «Обед», «Коворкинг».
4. Добавить Geolocation (текущая позиция).
5. Тестирование:
   - на реальном устройстве
   - на разных разрешениях
   - edge-кейсы (нет пути, все кластеры пустые и т.д.)
6. Документация:
   - в `docs/algorithms.md` — краткое описание каждого алгоритма
   - скриншоты
   - инструкция по запуску

- Красивая визуализация муравьёв/генетики/дерева.
- Экспорт маршрута в PDF или поделиться.
- Темизация под ТГУ + логотип.
